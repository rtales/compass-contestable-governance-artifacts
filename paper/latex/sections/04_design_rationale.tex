\section{Design Properties and Their Limits}
\label{sec:design}
\textbf{G1: Rule-aligned audit.} Metrics and constraint checks use the decision states emitted by the specified rule. A training-score metric cannot substitute for evaluation of that rule. The analysis identifies the policy and schema associated with each output.

\textbf{G2: Reproducible policy selection.} Given the same scored cases, IDs, candidate domain, objectives, policy and numerical conventions, the implementation applies exact Pareto filtering and deterministic tie-breaking. Tests include permuted cases and candidates. This property concerns computational reproducibility under fixed inputs; new training samples and institutional preferences can change the result.

\textbf{G3: Explicit failure.} An empty feasible set or insufficient evidence closes the schema 2.0 export gate while preserving candidate evidence. Legacy violation records document empirical failures without establishing that such a block occurred. The generated review-required record needs an institutional process to initiate and complete human review.

\textbf{G4: Evidence integrity.} The verifier checks packet hashes, policy content, dataset-manifest bytes, fitted-model bytes, schema fields and decision replay. Hash verification does not require deserializing the model. These checks establish internal consistency within the declared evidence boundary. Source-data truth, external authenticity and meaningful access to recourse require additional safeguards.

All numerical constraints are retrospective sample checks. New cases require monitoring and an appropriate evaluation design. Raising an entropy threshold can increase automation while admitting more errors; the policy analysis measures that trade-off without establishing improved educational outcomes.
